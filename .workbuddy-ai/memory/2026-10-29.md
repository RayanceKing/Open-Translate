# 2026-10-29

## Open Translate 0.2.0：设置页 + 多引擎重构

**背景**：项目原为 140 行左右的极简双语翻译工具（Tampermonkey 脚本 + MV3 扩展）。需求是补齐类似 immersive-translate 旧版设置页，支持切换翻译引擎、双语显示样式、AI Token 填写。

**架构决策**
- 设置统一为一个 `settings` 对象存 `chrome.storage.local`（脚本用 GM 存储），默认值/合并/归一化集中在 `extension/lib/defaults.js`，扩展与脚本各维护一份等价 DEFAULTS（content script 不能用 ES module）。
- 引擎抽象为 `lib/engines.js` 的 `translateTexts({engine, texts, source, target, config}) -> string[]`，支持批量；AI 引擎（openai/deepseek/gemini/claude）走编号批量 + 解析失败自动降级为逐段请求。
- 脱敏在 background 集中处理（`lib/privacy.js`），content 只负责文本抽取与渲染。
- AI 的 prompt/glossary/temperature 放在全局 `settings.ai`，引擎配置只留 key/baseUrl/model，避免设置页出现四套重复表单。
- 三种显示模式：bilingual（兄弟节点插入）、translation（清空元素 innerHTML 并记录原 HTML 以便还原）、hover（默认隐藏 + JS mouseenter 显示）。LI/TD/TH/DD/DT/BLOCKQUOTE 追加到元素内部以保留缩进。

**文件**
- 新增 `extension/lib/{defaults,engines,catalog,privacy,store}.js`
- 新增 `extension/options.{html,css,js}`（左侧导航 + 7 个分区 + 实时预览 + 导入导出 + 主题切换）
- 新增 `extension/popup.css`，重写 popup/background/content
- 重写 `tampermonkey/open-translate.user.js`：Shadow DOM 内嵌设置面板（通用/样式/引擎/AI 四个 tab），同样 9 个引擎
- README 全面更新

**验证方式（可复用）**
无头 Edge 截图做视觉检查：
`"/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge" --headless=old --no-sandbox --disable-gpu --hide-scrollbars --window-size=W,H --screenshot=out.png --virtual-time-budget=3500 URL`
扩展页面无 chrome API 时用 `_mock-chrome.js` 注入 storage/runtime/tabs 假实现，再配合 `?only=<section>&theme=light` 参数只渲染单个分区。content.js 也可用同样方式 stub `chrome.runtime.sendMessage` 单独验证渲染。注意：`--load-extension` 在无头模式下不生效，无法端到端验证扩展注入；`python3 -m http.server` 必须用 run_in_background，否则命令结束即被回收。

**踩坑**
- options.css 的深色媒体查询必须放在基础规则之后，否则同优先级基础规则覆盖深色值（userscript 里踩过）。
- 设置页里 services 列表的点击监听要绑在固定容器上，不能在每次 render 时重复绑定，否则监听器累积。
- 译文用 `display:inline-block` 而不是 block，虚线下划线才不会横贯整行。
- 开关被拉宽成 118px：`.field label { flex: 0 0 118px }` 特异性(0,1,1) 高于 `.switch { flex: 0 0 auto }`(0,1,0)，把 `<label class="switch">` 也一起命中了。改成 `.field > label:not(.switch)`，并给开关加 `margin-left:auto` 右对齐。

## 悬浮球（Immersive Translate 风格）

- 原右下角横条 `.ot-panel` 全部换成 44px 圆球 `.ot-dock` + 悬停展开的 `.ot-menu`（绝对定位在球的左/右侧，不占布局宽度，球的位置不会随引擎名长短漂移）。
- 拖动：pointerdown/move/up + setPointerCapture；移动超过 4px 才算拖拽。**切换逻辑放在 click 里，拖拽结束后 350ms 内用 suppressClick 吞掉紧随其后的 click**，否则松手会误触发翻译。
- 吸附：松手按球心与视口中线比较决定 left/right，`left = 10` 或 `innerWidth - 54`，top 存成 0–1 比例，随 `settings.ui.dock = {side, top}` 持久化；resize 时重新计算。
- 位置写入会触发 `chrome.storage.onChanged`，content script 用 `dockWriteAt` 时间戳（600ms 内忽略）避免自己写的变更触发"重新翻译整页"。

## 严重 bug（已修）：油猴脚本 TDZ 崩溃

`let settings = loadSettings()` 写在文件顶部，而 `loadSettings` 内部会调用 `deepMerge` → `isPlainObject`（`const` 声明在更后面）。首次安装时 GM_getValue 返回 null 不触发合并，所以测试没暴露；**一旦用户保存过设置，再次加载就会抛 `Cannot access 'isPlainObject' before initialization`，整个脚本挂掉**。修法：把初始化挪到合并函数定义之后，并在注释里说明原因。
教训：给 userscript 做 stub 测试时，必须同时覆盖"无存储"和"有存储"两条分支，只测 `GM_getValue = (k,d) => d` 会漏掉这类初始化顺序问题。

## 悬浮球最终形态（用户反馈后调整）

用户嫌横向胶囊菜单（翻译此页 / 引擎名 / ⚙）冗余，改为**竖向堆叠**：32px 齿轮圆钮在上、44px 翻译球在下，间距 6px，整组一起拖动吸附。横向 `.ot-menu` 相关 CSS/JS 已全部删除，引擎名改放到齿轮的 `title` 里（`设置 · 当前引擎：Google`）。
因为多了齿轮，dock 高度从 44 变成 ~82：`top` 仍按 0–1 比例存**整组中心**，应用时 `top = ratio*innerHeight - height/2`，拖拽与吸附的 clamp 都要用 `dock.offsetHeight`，否则球会跑出屏幕底部。

## Microsoft 翻译改为免费优先（Bing 公开通道）

**动机**：用户质疑「为什么微软翻译要填密钥，immersive-translate 里不是免费的吗」。确实，早期沉浸式翻译的微软通道就是免费的，只有 Azure 订阅才需要 key。

**实现**（`extension/lib/engines.js` + userscript 同名函数）
1. `GET https://www.bing.com/translator`（会 302 到 `cn.bing.com`，所以 host 必须从 `response.url` 取 origin，不能写死）。
2. 正则抓三样：`IG:"([0-9A-Fa-f]+)"`、`data-iid="([^"]+)"`、`params_AbusePreventionHelper\s*=\s*\[\s*(\d+)\s*,\s*"([^"]+)"\s*,\s*(\d+)` → key / token。
3. `POST {host}/ttranslatev3?isVertical=1&IG=..&IID=..`，body 是 `fromLang=auto-detect&to=..&text=..&token=..&key=..`。
4. 凭证缓存 8 分钟；401/403 时清缓存、重新抓一次并重试（`error.retryable`）。逐段请求，因为该端点一次只吃一段文本。
5. `settings.engines.microsoft = { useKey:false, key:'', region:'global' }`，`useKey` 为 false 走免费，true 走 `api.cognitive.microsofttranslator.com`。

**关键坑：缺 User-Agent 会返回 401 `{"ShowCaptcha":false}`**
Node 的 fetch 默认不带浏览器 UA，所以本地测试一开始「凭证已过期」，看起来像 token 抓错了。做了请求头矩阵实验才定位：
- 无 UA 无 cookie → 401
- 只有 UA（Chrome 或 Safari 任意）→ **200**
- 只有 Referer / 只有 Accept-Language / 只有 cookie → 401
所以 UA 是唯一硬性条件，cookie 可有可无。浏览器里 fetch 会自动带真实 UA（禁止手动设置，设了也会被静默忽略），因此浏览器环境本来就正常；显式写 `BROWSER_HEADERS` 只是为了 Node 下能自测。另外 `https://edge.microsoft.com/translate/auth` 已 404，那条老路子彻底失效，别再试。

**旧配置迁移**：0.2.0 之前 microsoft 只有 `{key, region}` 没有 `useKey`，直接合并默认值会让填过 key 的用户静默掉回免费通道。修法是在 `normalizeSettings` / `loadSettings` 里检查**原始存储对象**（不是合并后的结果，因为合并后 `useKey` 已被默认值填成 false）：`useKey === undefined && key 非空 → useKey = true`。

**设置页条件字段**：catalog 的 field 加 `dependsOn: 'useKey'`，渲染时若依赖未勾选就加 `hidden`；勾选变化时 `syncServiceDeps(card)`（扩展）/ `syncFieldDeps()`（脚本）重算 `field.hidden`。注意 userscript 面板只渲染当前选中引擎的字段（`ENGINE_FIELDS[engine]`），且用 `data-k="engines.<id>.<key>"` 定位，不是 id。

## 无头浏览器验证的两个新教训

- **`file://` 下 ES module 直接被 CORS 拦掉**，页面会「渲染出骨架但列表全空」，很容易误判成 JS 报错。必须 `python3 -m http.server` 起本地服务再截图。
- **主题切换有竞态**：`applyTheme()` 会在每次保存后按 `settings.ui.theme` 重新执行，harness 里一次性设 `dataset.theme='light'` 会被它改回去，表现为「卡片是浅色、按钮却是深色」的诡异截图。改成 200ms 间隔反复断言即可。
- 想截长页面的某个区块，别用 `scrollIntoView`（无头下会截到重绘残影，整页错位），改成在 harness 里 `remove()` 掉前面的卡片，让目标自然落在首屏。

## 翻译缓存改为会话级（用户要求「翻译结果要暂时缓存」）

**原实现的真问题**：缓存是 `background.js` 里一个模块级 `Map`。MV3 的 service worker 空闲约 30 秒就被回收，模块状态随之清空——用户切个标签页回来、或页面刷新，缓存就没了，整页重译。

**方案：双层 + 「暂时」语义**
- L1：SW 内的 `Map`，命中零开销。
- L2：`chrome.storage.session`（Chrome 102+）。它**只存在内存、不落盘**，SW 重启保留，浏览器关闭即消失——正好就是「暂时缓存」该有的生命周期，比 `storage.local` + TTL 更干净。
- 脚本版用 `sessionStorage`（同标签页刷新保留，关标签页清空）。
- 另有 TTL 12 小时 + 上限 2000 条，避免浏览器几天不关时长期供应陈旧译文。

**关键实现细节（`extension/lib/cache.js`）**
- **key 用指纹而不是原文**：`engine|target|source|saltFingerprint|textFingerprint`，64 位双 FNV-1a。好处是缓存里根本不存在原文，翻存储也看不出用户读过什么；顺带体积小。
- **salt 承载「改变译文但不改变原文」的因素**：AI 引擎时为 `prompt + glossary + temperature`。原实现的 key 只有 `engine|target|text`，**改了提示词或术语表还会命中旧译文**，这是个真 bug，一并修掉。
- **hydrate 必须并发安全**：`writeCache` 是同步的，而 L2 读取是异步的。若先写后读，flush 会用不完整的 Map 覆盖已有缓存。做法是 `hydrating` 缓存同一个 promise，且 `flush()` 开头先 `await hydrate()`，load 时用 `if (memory.has(key)) continue` 避免覆盖刚写入的新值。
- 落盘 400ms 防抖；`storage.session` 超配额时丢一半重试一次，失败就退回纯内存。
- LRU 用 Map 天然保序：命中时 `delete` 再 `set` 移回队尾。

**验证方式（可复用）**
- `cache.js` 单测：用假 `chrome.storage.session` 共享一个对象，再 `import('./cache2.mjs')` 导入**同一份文件的副本**拿到全新模块实例——等价于 SW 重启（L1 空、L2 有数据），12 项断言全过。
- `background.js` 集成测试：stub `chrome.storage`/`runtime.onMessage`/`fetch`，直接调用捕获到的 listener，用 fetch 调用次数判断命中：首翻 2 次、重翻 2 次（+0）、换语言 4 次（+2）、混合 5 次（+1）。
- 脚本版在浏览器里用 `GM_xmlhttpRequest` 计数 stub：首翻 3 次请求，还原后再翻仍是 3 次。

**入口**：设置页「隐私与安全 → 翻译缓存」（显示条数 + 清空按钮，走 `cache-stats` / `clear-cache` 消息）；脚本面板「通用 → 翻译缓存」。`test-engine` 走的是 `translateTexts` 而非 `handleTranslate`，所以测试连接的样句不会污染缓存。
