### Test harness gotcha (headless)
`--virtual-time-budget` + autoplay races the VTT load. If `startCueDriver` is called AFTER a pre-wait while the video already autoplays, the immediate `onCue()` sees empty `activeCues` and `cuechange` doesn't re-fire → overlay stays empty (false failure). Fix: call `startCueDriver` immediately and attach the `cuechange` listener BEFORE `video.play()`.

### Code observation (real, not test-only)
In `startSubtitles` track-mode path, only the TextTrack `cuechange` driver is wired. The rAF + timeupdate + watchdog "three drivers" net (`startSubTick`/`bindSubVideo` in userscript ~L1148/1222) is **never kicked off in track mode** — `bindSubVideo` is only called from inside `ensureSubVideo`, which is only reached from `startSubTick`'s own loop. So if `cuechange` ever fails to fire in a real browser, track-mode subs render nothing with no fallback. Worth wiring `bindSubVideo(video)` into track-mode `startSubtitles` for resilience.
