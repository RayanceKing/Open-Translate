## Fixed: track-mode subtitle resilience net now actually wired
File: `tampermonkey/open-translate.user.js`, in `startSubtitles()` track-mode branch, right after `const ok = await startCueDriver(video, cues); if (!ok) {...}`:

```js
bindSubVideo(video);
if (!video.paused) startSubTick();
```

Why: previously track mode relied solely on the injected `<track data-ot>` `cuechange` event. `bindSubVideo`/`startSubTick` (rAF + timeupdate + watchdog) were dead code in track mode — `bindSubVideo` was only reachable from `ensureSubVideo`, itself only reachable from `startSubTick`'s own loop. If `cuechange` stalled (some players/browsers), the overlay froze at the first cue with no fallback. Now the tick net drives `updateCue()` off `video.currentTime` as a second driver. `if (!video.paused) startSubTick()` handles the autoplay case where the `play` event already fired before binding.

Safety: `ensureSubTranslated` dedupes via `SUB.pending` + `translation !== null`, so dual drivers cause no duplicate translation calls. `updateCue` guards `index === SUB.index`. Teardown already covered by `stopSubtitles()` → `stopSubTick()` + `unbindSubVideo()`.
