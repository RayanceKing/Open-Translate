## Fixed: track-mode subtitle resilience net now actually wired
File: `tampermonkey/open-translate.user.js`, in `startSubtitles()` track-mode branch, right after `const ok = await startCueDriver(video, cues); if (!ok) {...}`:

```js
bindSubVideo(video);
if (!video.paused) startSubTick();
```

Why: previously track mode relied solely on the injected `<track data-ot>` `cuechange` event. `bindSubVideo`/`startSubTick` (rAF + timeupdate + watchdog) were dead code in track mode — `bindSubVideo` was only reachable from `ensureSubVideo`, itself only reachable from `startSubTick`'s own loop. If `cuechange` stalled (some players/browsers), the overlay froze at the first cue with no fallback. Now the tick net drives `updateCue()` off `video.currentTime` as a second driver. `if (!video.paused) startSubTick()` handles the autoplay case where the `play` event already fired before binding.

Safety: `ensureSubTranslated` dedupes via `SUB.pending` + `translation !== null`, so dual drivers cause no duplicate translation calls. `updateCue` guards `index === SUB.index`. Teardown already covered by `stopSubtitles()` → `stopSubTick()` + `unbindSubVideo()`.

## Changed: page translation is now lazy / viewport-driven (Immersive-Translate style)
Files: `extension/content.js` and `tampermonkey/open-translate.user.js` (identical logic in both).

Why: enabling translation used to call `scan(document)` → `enqueue` every block immediately, mounting "翻译中…" for the whole page and firing all requests at once. That is exactly what trips engine rate limits / risk control. Now only blocks the reader is about to see are translated.

How:
- New state: `pending` (Set of blocks awaiting translation), `intersectionObserver`, `lastIoAt`, `flushScheduled`, `LAZY_ROOT_MARGIN='400px 0px'`, `LAZY_MARGIN_PX=400`.
- `scan()` now only adds targets to `pending` and `io.observe()`s them; it no longer enqueues eagerly.
- Primary trigger: IntersectionObserver (`rootMargin` 400px). On intersect: `unobserve` → `pending.delete` → `enqueue`.
- Fallback: `flushVisible()` checks `getBoundingClientRect()` against `innerHeight ± 400px` and enqueues in-view pending blocks. Driven by `scroll`/`resize` (capture+passive) via `scheduleFlush()` (16ms `setTimeout`, not rAF — rAF is inert in some webviews/headless).
- `scheduleFlush()` skips the rect scan while `Date.now() - lastIoAt < 500` (IO recently delivered), so IO remains the efficient primary path and the fallback only takes over when IO stalls. (A plain `ioAlive` boolean was tried first and was too aggressive: headless fires IO once then stalls, permanently disabling the fallback.)
- `start()` calls `flushVisible()` synchronously after `scan()` so above-the-fold translates immediately.
- `restore()` clears `pending`, disconnects IO, resets `lastIoAt`, `translating`.
- Removed the old `if (queue.length > 80) return;` guard in the MutationObserver; `scan()` now only observes, so it is unnecessary and could permanently skip new nodes.
- Bootstrap calls `watchViewport()`.

Headless caveats learned: under `--headless=new --virtual-time-budget`, IntersectionObserver never fires (`fired:0`), `requestAnimationFrame` never fires (`raf:0`), and `window.scrollTo` does not dispatch a `scroll` event (but does change `scrollY`). `setTimeout` and `getBoundingClientRect` work. Tests therefore dispatch a synthetic `scroll` event and rely on the setTimeout-driven rect fallback.
